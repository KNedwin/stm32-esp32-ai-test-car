# 常见问题清单

> 20 个 Q&A，5 类各 4 个

## 1. 构建与烧录

### Q1（构建与烧录）：如何编译并烧录程序？
**A**：STM32：在工程目录执行 `cmake -B build && cmake --build build`，ST-Link 用 `st-flash write build/rfid_tts_rtos.bin 0x08000000`；2026-08 起新增免 ST-Link 方式——串口发 `ISP` 命令软跳系统 Bootloader 后 `stm32flash -w <bin> -v -g 0x0 /dev/ttyUSB0`（跳转前拔 U13T 读卡模块，其 RX 占用 USART1 干扰应答），或直接用 PC 上位机 tools/stm32_host 的编译/烧录按钮。ESP32：先 `source ~/.espressif/tools/activate_idf_v6.0.2.sh` 激活环境，再 `idf.py build`、`idf.py -p /dev/ttyACM0 flash monitor`。

### Q2（构建与烧录）：如何用串口命令行修改参数？（2026-08 更新）
**A**：USART3(PB10/PB11) 115200，行以 \r\n 结尾。`HELP` 列命令；`GET all\|win\|rule` 查询；`SET <key> <val>` 修改（标量键 late_s/slow_s/target/dir/sr_s/ws_s/led_s/dedup_s/poll_s/ci_s/as_s，单位秒；另有 win_add/win_del、rule_add/rule_del），每条修改成功即 params_apply 生效无需重启；`SAVE` 写 Flash 断电保持；`DUMP` 查看参数页原始字节；`ISP` 软跳 Bootloader 免 ST-Link 烧录；`REBOOT` 复位。应答同口 `> ` 前缀。图形化操作用 PC 上位机 tools/stm32_host（默认 http://127.0.0.1:8321）。

### Q3（构建与烧录）：CubeMX 重新生成工程后编译报错或行为异常（仅 STM32）？
**A**：重新生成会覆盖 4 处生成代码：USART2 波特率（须 9600）、TIM2 CH2（须 PWM2 + OCFastMode ENABLE）、ADC 采样时间（须 28.5 cycles）、FreeRTOSConfig.h 堆大小（须 8192）。业务代码在 hardware/Task/config.h 与 USER CODE 区，不受影响。

### Q4（构建与烧录）：任务栈溢出/FreeRTOS 内存不足怎么调（仅 STM32 RTOS 版）？
**A**：RFID_TASK 栈 1024 字、Motor_Control 512 字、defaultTask 512 字（2026-08 由 128 扩容以承载 CLI 解析+格式化打印）、堆 8192。若链接报 RAM 超限应减小堆或栈；若运行时任务创建失败（osThreadCreate 后句柄为 NULL）才增大堆。

## 2. 读卡与协议

### Q5（读卡与协议）：读卡没反应怎么办？
**A**：① 确认波特率切换代码在 usart.c（STM32）/card_uart.c（ESP32）的初始化中执行（9600 发 0x2C → 115200）；② 读卡模块供电 3.0~5.5V 并共地；③ 卡片在感应区；④ 检查帧解析：模块响应 0x7F 开头，长度≤31。

### Q6（读卡与协议）：为什么开机波特率切换时读卡可能失效（STM32 版已修复）？
**A**：9600 期模块 0xAC 响应若在接收中断使能前到达会造成 ORE 溢出锁死。修复：初始化先使能接收（清乱码）再发切换命令，并实现 HAL_UART_ErrorCallback 自愈。ESP32 版 IDF 驱动环形缓冲天然免疫。

### Q7（读卡与协议）：帧长度字段超过 31 会怎样？
**A**：解析器会丢弃整帧并复位状态机（长度上限防护），不会越界写 ReceiveBuffer[32]。

### Q8（读卡与协议）：卡数据包含 0x7F 字节会怎样？
**A**：发送侧做了 0x7F 双写转义；接收侧未做反转义（遗留低危项）。GBK 汉字字节范围 0x81~0xFE 不含 0x7F，正常中文卡数据不会触发。

## 3. 触发词与去重

### Q9（触发词与去重）：如何添加新的触发词？
**A**：（2026-08 起两种方式）① 免编译：串口发 `SET rule_add BBF0D0C7 1 1`（GBK hex + 触发次数 + 是否播报），`SAVE` 保持，`GET rule` 核对，上限 8 条；② 编译期：改 config.h 的 TRIGGER_RULES 表（Python 算 GBK 字节，同步 len）。运行时规则经 RfidLogic_SetConfig 注入。

### Q10（触发词与去重）：为什么"太阳"只触发一次，之后只播报？
**A**：设计为一次性触发词（count_req=1）：第 1 次读到播报+停车并置 triggered 标志，整个上电周期内不再触发，断电重启才恢复。

### Q11（触发词与去重）：为什么"地球"需要读两次才触发？
**A**：地球是计数型触发词（count_req=2）：第 1 次只播报亮灯并计数，第 2 次（距上次计数 ≥10s）才播报+停车；10s 内连刷不计次数。

### Q12（触发词与去重）：D 秒去重是什么？为什么触发词不受去重限制？
**A**：D=10s 内相同内容不重复播报（普通卡）。触发词的播报是强制播报（不受去重约束），因为触发事件必须播报；播报后会更新去重记录。

## 4. 电机控制

### Q13（电机控制）：电机不转或方向不对？
**A**：① STM32：确认 TIM2 两通道都是 PWM Mode 2（CH2 常被生成成 PWM1，需手工改）；② 检查速度参数 0~999；③ 电机驱动板供电；（2026-08 起）④ 方向反了不用改线：串口发 `SET dir 1`（或上位机转向开关）交换 CH1/CH2 差分角色即反转，SAVE 后保持；⑤ ESP32 检查 LEDC 接线。

### Q14（电机控制）：缓启动/减速不平滑（一顿一顿）？
**A**：属正常现象：STM32 裸机版 TTS 发送（9600 单块 16 字节约 17ms）期间主循环停顿；ESP32 版 100Hz 节拍 vTaskDelay(1)=10ms 步进。功能不受影响，可增大缓启动时长 B 更柔。

### Q15（电机控制）：停车重启后立即 STOP（再也不转）？
**A**：这是绝对计时的边界行为：stop_time=autostop_ms 是上电后总时长（2026-08 起默认 5 分钟、参数可调），若停车序列（H+I）+ 已运行时间越过它，重启进 RUN 的瞬间即 STOP。可用 `SET as_s <秒>` 加长或改相对计时（设计决策）。

### Q16（电机控制）：E=42s 降速窗口为什么重启后可能再次降速？
**A**：窗口按绝对时间 t∈[42s,47s) 判定；若触发停车重启后 t 仍落在窗口内（触发发生在 26~31s 区间），会再次降速到窗口结束。这是绝对时间语义的合理行为。

### Q17（电机控制）：自动停车时间怎么调？（2026-08 更新）
**A**：电位器采样已退役，停车时间=参数 autostop_ms（上电到永久停车总时长，默认 300000ms=5 分钟）。串口发 `SET as_s 15` 即改为 15 秒并即时生效，`SAVE` 断电保持；范围 10~1000 秒。MotorLogic_CalcStopTime 公式保留在共享层但已无调用方。

## 5. LED 与调试

### Q18（LED 与调试）：LED 为什么卡在线圈上一直亮、移开后不立即灭？
**A**：设计如此：卡在线圈上时读卡号响应持续刷新卡在场时间戳，LED 常亮；移开卡后约 C=3s（LED_ON_TIME_S）熄灭。

### Q19（LED 与调试）：数据输出口看不到输出/乱码？
**A**：STM32：USART3 115200（screen /dev/ttyUSB0 115200）；ESP32：USB-Serial-JTAG console（idf.py monitor）。检查波特率与接线交叉；LED/电机输出为边沿触发（状态变化才输出一行），读卡数据每条输出。

### Q20（LED 与调试）：调试输出影响实时性吗？
**A**：输出口每行 <40 字节：STM32 USART3 115200 约 3ms、ESP32 console 微秒级，影响可忽略；RTOS 版两任务并发输出时可能丢一条（HAL 返回 BUSY），不影响功能。
