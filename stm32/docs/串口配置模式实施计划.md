# STM32 串口配置模式实施计划（PC 上位机 + 参数化 + 免拆烧录）

> 目标：让没有网络的 STM32 版拥有与 ESP32 一致的体验——
> 用一个 PC 本地专用界面（网页形式）修改全部系统参数，
> 并在同一界面里完成固件的**编译**与**烧录**。
> 全程只需一根 USB-TTL 线接调试串口（USART3），现场更新不需要 ST-Link。

---

## 0. 与 ESP32 方案的对齐映射

| 能力 | ESP32 实现 | STM32 对应实现 |
|---|---|---|
| 配置入口 | 连按3次RST开WiFi热点 | 插上USB-TTL即用（无需手势，常驻CLI） |
| 参数界面 | 内嵌 webpage.html @ 192.168.4.1 | PC 本地网页（复用同一套表单，API 指向串口桥） |
| 参数存储 | NVS blob | 内部 Flash 末页（0x0800FC00，CRC 校验） |
| 中文触发词 | 固件内置 GB2312 表转换 | **PC 侧转 GBK**（Python 自带 cp936），固件纯 ASCII 协议 |
| 固件升级 | OTA 不适用/重启即刷 | ①ST-Link/OpenOCD（开发）②串口 ISP 软跳转（现场，备选） |
| 参数体系 | params_t (nvs_params) | params_t (params_store)，**结构与字段与 ESP32 完全同构** |

> 设计原则：能对齐的全部对齐——参数字段、默认值、网页表单、语义说明四者与 ESP32 版一致；
> 差异只在传输层（HTTP/WiFi → 串口/COM）和存储层（NVS → Flash 末页）。

## 阶段一：参数层重构 + Flash 末页存储（核心工作量）

### 1.1 逻辑层 Setter 注入改造（STM32 副本照搬 ESP32 已验证 diff）
- `motor_logic.c/h`：加入 `motor_timing_t`/`MotorLogic_SetTiming()`/`MOTOR_TIMING_DEFAULT`
  （直接从 esp32/components/common/motor_logic.c/h 搬运，逐字相同恢复四版一致性）
- `rfid_logic.c/h`：加入 `rfid_rule_rt_t`/`RfidLogic_SetConfig()` 运行时规则表
- 应用调用点改造：`MotorLogic_Init` 改传 `g_params.target_speed / g_params.autostop_ms`
  （自动停车时间同步网页化，电位器采样移除——与 ESP32 B 方案对齐）

### 1.2 新增 `params_store.c/h`
- 参数结构 `params_t`：字段集与 ESP32 `nvs_params.h` **完全同构**
  （late/slow/target/dir/slowwins[8]/rules[8]/count_interval/stop_ramp/wait/led_on/dedup/poll/autostop）
- 存储：Flash 末页 0x0800FC00（1KB）
  布局：magic(0xA55A)+ver+len+payload+CRC16；校验失败→回落 config.h 默认宏
- API：`params_init()`(读末页+CRC)/`params_save()`(擦写+CRC)/`params_sanitize()`（钳制规则与 ESP32 相同）
- ⚠️ 读写期间关中断保护；保存频率低，磨损无忧

### 1.3 移除电位器依赖
- `Motor_Init` 删除 ADC 20 次采样循环 → stop_time 直接取 `g_params.autostop_ms`
- 默认值 300000ms(5分钟)，网页范围 10~1000 秒

### 1.4 测试
- 主机单测同步 ESP32 的注入式改造（test_motor_logic/test_logic 补 SetTiming/SetConfig 用例）
- 全绿后再进阶段二

## 阶段二：串口 CLI 文本协议（预计半天）

### 2.1 USART3 收发改造
- 现状：USART3 只发不收（Dbg_Printf 出方向）
- 新增：115200 8N1 接收（中断或轮询环形缓冲），按 \r\n 分行送解析器
- 与 Dbg_Printf 共存：输出仍走原路；CLI 应答以 "> " 前缀区分

### 2.2 协议（纯 ASCII，行尾 CRLF）
```
GET all                 → 单行 JSON 回显全部参数
SET late_s 2            → 标量赋值（秒单位，固件×1000）
SET dir 1               → 转向
SET win_add 42 5 50     → 追加减速窗口(秒/秒/百分比)
SET win_del <idx>
SET rule_add <gbk_hex> <count> <speak>   → 词为 GBK hex（PC 侧已转换）
SET rule_del <idx>
SAVE                    → sanitize + 写 Flash 末页，回 OK/ERR
DUMP                    → 十六进制 dump 当前存储页（诊断用）
ISP                     → [备选] 软跳系统 Bootloader（见阶段三）
REBOOT                  → 软复位
ERR:unknown / ERR:range / OK:<value>       ← 错误约定
```

## 阶段三：ISP 软跳转免拆烧录（备选能力，2 小时）

- 收到 `ISP` 命令：关中断 → 设置 MSP=0x20005000 → 跳转 0x1FFFF000（系统 Bootloader）
- 之后 PC 端 `stm32flash -p COMx -w new.bin` 即可刷新固件（无需 ST-Link/BOOT0 跳线）
- ⚠️ 前提：临时拔掉 U13T 读卡模块（其 RX 占用 USART1，会干扰 Bootloader 应答）
- 定位：现场无 ST-Link 时的兜底手段；日常开发仍推荐 ST-Link

## 阶段四：PC 上位机（预计一天）

### 4.1 形态
- Windows 本机运行 Python 脚本（pyserial + 内置 http.server）
- 启动后自动打开浏览器 `http://127.0.0.1:8321`
- 页面表单**直接复用 ESP32 的 webpage.html**（API 层改为转发到串口）

### 4.2 功能
- COM 口下拉自动枚举（pyserial list_ports）
- 参数 GET/POST：POST 时 UTF-8 触发词在 PC 侧编码为 GBK hex 再下发
- **工具页签**：
  - [编译] 按钮 → subprocess 调 WSL：`wsl bash -c "source ... && cmake --build build"`，实时回显输出
  - [烧录] 按钮 → 两种模式：ST-Link(openocd/st-flash) 或 串口ISP(先发ISP命令再 stm32flash)
  - 输出日志窗口

### 4.3 目录
```
tools/stm32_host/
├── host.py          # 入口：http.server + pyserial 桥
├── page.html        # 复用 ESP32 表单（API 地址不同）
└── README.md
```

## 风险与注意

| 风险 | 对策 |
|---|---|
| 逻辑层 Setter 重构量大 | 照搬 ESP32 已验证 diff，小步走每文件编译+单测 |
| USART3 首次加接收 | 环形缓冲+分行解析独立成模块，不影响 Dbg_Printf |
| Flash 末页擦写期间中断 | 写前关中断，写后恢复 |
| ISP 跳转需拔 U13T | 文档标注；日常优先 ST-Link |
| 上位机跨 Win/WSL | 编译用 wsl.exe 包装；串口在 Windows 侧直连最稳 |
