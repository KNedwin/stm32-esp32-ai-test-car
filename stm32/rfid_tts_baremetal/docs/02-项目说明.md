# 裸机版 - 项目说明

> 配套文档：《01-CubeMX从零教程.md》（如何生成工程）。本文说明"这个项目是什么、参数怎么调、代码怎么组织"。
> 与 RTOS 版相比，**功能完全一致**，区别仅在内部实现（无操作系统，主循环 + 状态机）。

---

## 1. 功能规格

| # | 功能 | 规格 | 对应 config.h 参数 |
|---|---|---|---|
| 1 | 晚启动 | 通电延时 **A** 秒后电机才开始转 | `MOTOR_START_LATE_TIME_MS` |
| 2 | 缓启动 | 从 0 用 **B** 秒线性加速到目标速度 | `MOTOR_START_SLOW_TIME_MS` |
| 3 | 实时读卡 + LED | 任意时刻轮询读卡；读到卡 LED 亮；**卡在线圈上持续亮**，卡脱离 **C** 秒后熄灭 | `LED_ON_TIME_S` |
| 4 | 语音播报 | 卡内 GBK 数据（**单块 16 字节**）送 TTS 播报；**D** 秒内相同内容不重复播报（LED 不受影响） | `SPEAK_DEDUP_TIME_S` |
| 5 | 定时降速 | 电机运行到第 **E** 秒时速度降为 **F%**，持续 **G** 秒后恢复（**绝对计时，开机后仅一次**） | `MOTOR_TIME_START_S` / `MOTOR_SPEED_PERCENT` / `MOTOR_TIME_DURATION_S` |
| 6 | 触发停车 | **多触发词规则表**（config.h 可配）：命中规则的卡触发电机停车序列，每个词**整个上电周期只触发一次** | `TRIGGER_RULES` / `TRIGGER_STOP_RAMP_TIME_S` / `TRIGGER_WAIT_TIME_S` |
| 7 | 电位器自动停止 | 按电位器阻值计算停车时间（10s~600s，**绝对计时**），到时停车 | `RES_MAX` / `STOP_TIME_MIN_MS` / `STOP_TIME_MAX_MS` |
| 8 | 数据输出串口 | USART3（115200）实时输出读卡数据、电机状态、LED 状态 | `DBG_*` |
| 9 | 系统保护 | 程序卡死（HardFault）自动重启 | — |

### 触发停车详细时序（功能 6）

```
读到命中触发词的卡（单块16字节内子串匹配）
   │
   ▼
STOPPING：花费 H 秒线性减速（当前速度 → 0）      ← H = TRIGGER_STOP_RAMP_TIME_S = 2
   │
   ▼
WAIT：电机静止等待 I 秒                          ← I = TRIGGER_WAIT_TIME_S = 10
   │
   ▼
RAMPUP：重新缓启动 B 秒（不再经过晚启动 A）──▶ RUN
```

- 从触发到重新起步，共 **H + I = 12 秒**（2 秒减速 + 10 秒静止）
- 减速起点 = 触发时刻的**当前速度**（可能是目标速度，也可能是降速窗口内的 F% 速度）
- 电机时间轴为**上电绝对计时**：停车重启后计时**不清零**；E 秒降速窗口**开机后仅生效一次**（重启后不再降速）；电位器 stop_time / 1000s 上限仍按绝对时间生效
- ⚠️ 边界行为（绝对计时的必然结果）：若触发停车时已运行较久，停车序列结束后重启时，若 `t ≥ stop_time` 已满足，则**起步瞬间立即 STOP**（不再转）

### 触发词规则表（config.h 变量化）

```c
typedef struct {
    const uint8_t *word;      /* GBK 字节序列（变量，可改） */
    uint8_t        len;       /* 字节数（变量，可改） */
    uint8_t        count_req; /* 触发所需次数（变量，可改） */
    uint8_t        speak_en;  /* 触发时是否播报（变量，可改） */
} trigger_rule_t;

#define TRIGGER_RULES \
  { (const uint8_t*)"\xCC\xAB\xD1\xF4", 4, 1, 1 },   /* "太阳"：1次触发，播报+停车 */
  { (const uint8_t*)"\xB5\xD8\xC7\xF2", 4, 2, 1 }    /* "地球"：2次触发(间隔≥10s)，播报+停车 */

#define TRIGGER_COUNT_INTERVAL_MS  (10*1000)  /* 计数型词两次有效计数最小间隔 */
#define TRIGGER_STOP_RAMP_TIME_S   2          /* H：减速过程耗时(秒) */
#define TRIGGER_WAIT_TIME_S        10         /* I：停住后静止等待(秒) */
```

**修改方法**（触发词内容随时可改，只动 config.h）：
1. 用 Python 计算新词 GBK 编码：`python -c "print(' '.join('\\x%02X' % b for b in '新词'.encode('gbk')))"`
2. 把结果填入 TRIGGER_RULES 表新增一行（或替换某行），注意同步修改 `len`（2 个汉字 = 4）
3. 规则可增可删，代码自动按 `sizeof(TRIGGER_RULES)/sizeof(trigger_rule_t)` 计算条数，无需改逻辑
4. 目前所有触发词的动作统一为"停车 H+I 秒后重新缓启动"（后续如需不同动作可扩展）

### 触发词行为矩阵

| 场景 | 太阳（一次性，count_req=1） | 地球（计数型，count_req=2） |
|---|---|---|
| 第 1 次读到 | **播报 + 停车**，标记"已触发" | 播报 + 亮灯，计数=1（未达次数，按普通卡流程） |
| 第 2 次读到 | 正常播报亮灯（已触发，不再停车） | 距上次计数 **≥10 秒** → **播报 + 停车**，标记"已触发" |
| 触发之后 | 整个上电周期内不再触发，只播报亮灯（**断电重启才恢复**） | 同左 |
| 10 秒内重复刷 | 无影响（已触发） | 不计入次数（走普通播报流程） |
| 停车序列期间（H+I=12s） | 不计数、不触发（播报流程照常） | 不计数、不触发（播报流程照常） |
| 触发时播报 | 强制播报，**不受 D 秒去重约束**（播报后更新去重记录） | 同左 |
| LED | 始终照常亮 | 始终照常亮 |

> 注意：触发词"播报 + 停车"中的**播报内容就是卡内数据本身**（如"太阳"二字）。

## 2. config.h —— 全部可调参数（唯一修改入口）

> 修改参数后需重新编译。**与 RTOS 版参数完全一致**，两版代码可直接互换 config.h。
> ⚠️ 本文件宏名与案例 `user_setup.h` **不兼容**（参数含义对应但宏名不同），须连同 Task/ 层代码一起替换，不能单独替换 user_setup.h。

```c
#ifndef __CONFIG_H
#define __CONFIG_H

/* ================= 电机时序（功能1/2） ================= */
#define MOTOR_START_LATE_TIME_MS    2000    // A：通电延时(ms)后电机才启动。默认2秒
#define MOTOR_START_SLOW_TIME_MS    4000    // B：缓启动时长(ms)，0→目标速度线性加速。默认4秒
#define MOTOR_TARGET_SPEED          999     // 电机目标速度(0~999)。999=最高电压输出
#define MOTOR_SLOW_RAMP_STEP_MS     10      // 缓启动/减速的更新粒度(ms)。越小越平滑(阶梯越细)，10即可；裸机版受串口阻塞影响小，10~20均可

/* ================= 定时降速窗口（功能5） ================= */
#define MOTOR_TIME_START_S          42      // E：电机运行到第几秒开始降速。默认42秒
#define MOTOR_SPEED_PERCENT         50      // F：降速后速度 = 目标速度 × F%。50=一半速
#define MOTOR_TIME_DURATION_S       5       // G：降速持续几秒后恢复目标速度。默认5秒

/* ================= 触发词规则表（功能6） ================= */
typedef struct {
    const uint8_t *word;      /* GBK 字节序列 */
    uint8_t        len;       /* 字节数 */
    uint8_t        count_req; /* 触发所需次数（1=一次性词，>1=计数型词） */
    uint8_t        speak_en;  /* 触发时是否播报（1=播报） */
} trigger_rule_t;

#define TRIGGER_RULES \
  { (const uint8_t*)"\xCC\xAB\xD1\xF4", 4, 1, 1 },   /* "太阳"：1次触发，播报+停车 */
  { (const uint8_t*)"\xB5\xD8\xC7\xF2", 4, 2, 1 }    /* "地球"：2次触发(间隔≥10s)，播报+停车 */

#define TRIGGER_COUNT_INTERVAL_MS  (10*1000)  // 计数型词两次有效计数最小间隔(ms)。默认10秒
#define TRIGGER_STOP_RAMP_TIME_S   2          // H：触发停车减速过程耗时(秒)。默认2秒
#define TRIGGER_WAIT_TIME_S        10         // I：停住后静止等待(秒)。默认10秒

/* ================= LED 与播报去重（功能3/4） ================= */
#define LED_ON_TIME_S               3       // C：卡脱离线圈后，LED延迟熄灭时间(秒)。默认3秒
#define SPEAK_DEDUP_TIME_S          10      // D：相同内容去重窗口(秒)。默认10秒
#define RFID_READ_DELAY_MS          800     // 一次播报后到下次读卡的间隔(ms)。默认800ms
#define RFID_LED_POLL_MS            10      // LED亮灯期间轮询读卡的间隔(ms)。默认10ms

/* ================= 电位器自动停止（功能7） ================= */
#define RES_MAX                     5000    // 电位器阻值量程(用于线性插值)
#define STOP_TIME_MIN_MS            (10*1000)    // 停车时间下限：10秒
#define STOP_TIME_MAX_MS            (10*60*1000) // 停车时间上限：600秒(10分钟)

/* ================= 数据输出串口（功能8） ================= */
#define DBG_USART_ENABLE            1       // 总开关：1=启用输出
#define DBG_USART_BAUD              115200  // 输出串口波特率（需与上位机一致）
#define DBG_ECHO_RFID               1       // 1=输出读卡数据
#define DBG_ECHO_MOTOR              1       // 1=输出电机状态
#define DBG_ECHO_LED                1       // 1=输出LED状态

/* ================= 其他 ================= */
#define RFID_DEBUG_MODE             0       // 1=开启调试语音播报(比赛建议0)
#define RFID_READ_DATA_WHEN_START   1       // 1=开机就尝试读卡(默认)；0=等刷卡才读
#define RFID_SETTING_SPEAK_SPEED    1       // 1=开机设置语速/音量/保存(默认)

#endif /* __CONFIG_H */
```

### 修改建议

| 想达到的效果 | 改什么 |
|---|---|
| 电机启动更快 | 减小 `MOTOR_START_LATE_TIME_MS`（如 500） |
| 电机更柔 | 增大 `MOTOR_START_SLOW_TIME_MS`（如 6000） |
| 降低最高速度 | 减小 `MOTOR_TARGET_SPEED`（如 800） |
| 降速更明显 | 减小 `MOTOR_SPEED_PERCENT`（如 30） |
| 加/换/删触发词 | 按第 1 节"修改方法"改 `TRIGGER_RULES` 表 |
| 触发词变成"第 3 次才触发" | 该行 `count_req` 改为 3 |
| 触发词只触发不播报 | 该行 `speak_en` 改为 0 |
| 比赛场地 LED 亮久点 | 增大 `LED_ON_TIME_S` |
| 频繁刷卡不重复播报 | 增大 `SPEAK_DEDUP_TIME_S` |
| 电机缓启动更平滑 | 减小 `MOTOR_SLOW_RAMP_STEP_MS`（如 5，阶梯更细；开销略增，10 已足够平滑） |

## 3. 架构说明

### 3.1 总览：裸机双状态机

本版本没有操作系统，程序结构为：

```
main()
 ├── 初始化：时钟/外设/LED/PWM/ADC/调试口/读卡串口中断
 └── while(1) 主循环
      ├── RFID_Process()     读卡状态机（非阻塞）
      │     NONE → EXIST → RESDATA → [去重/触发判断] → 播报 → LEDLIGHT → ...
      └── Motor_Process()    电机状态机（非阻塞）
            IDLE → RAMPUP → RUN → [SLOW降速窗口] → [STOPPING → WAIT → RAMPUP]
```

两个函数每次调用**必须快速返回**（不阻塞），各自用 `HAL_GetTick()` 记录"上次动作时间"来实现延时等待，这样两个流程才能"同时"推进。

### 3.2 RFID 状态机（RFID_Process）

```
            读到卡               收到完整数据
  ┌────────┐   ───►  ┌────────┐  ────►  ┌──────────┐
  │  NONE  │         │ EXIST  │        │ RESDATA  │ 数据处理
  └────────┘         └────────┘        └──────────┘
       ▲                  ▲                  │
       │ 卡脱离C秒后        │20ms超时重发       ▼
       │                  └── CARD_FLAG_WAIT ◄── 等待读块响应
       │                                        │ 有数据(单块16字节)
       └────── 熄灭LED ◄──── LEDLIGHT ◄─────────┤ 规则表匹配
              (tick计时)     (每10ms轮询读卡     │  ├─ 命中规则 → 计数/触发判断（见行为矩阵）
                             卡在→刷新计时)      │  └─ 未命中 → 去重判断 → TTS播报
                                                 └→ 800ms延时(非阻塞)→LEDLIGHT
```

关键点（裸机实现）：
- **LED 常亮逻辑**：进入 LEDLIGHT 后每 10ms 发一次"读卡号"命令；收到正确响应（卡在）时**由 Card.c 回调刷新全局卡在场时间戳**；`HAL_GetTick() - 卡在场时间戳 >= C*1000`（卡已脱离）才灭灯回 NONE。此功能**需要修改 Card.c 回调**（见 4.1）。
- **单块读取**：与案例一致，只读一个块（16 字节）——块 4 有数据播报块 4，块 4 空回退块 1 播报其 16 字节。不做多块拼接，无越界风险。触发词匹配在**单块 16 字节内**做子串搜索。
- **播报缓冲按路径选择**：块 1 路径数据在 `Cmd.block_data`，块 4 路径数据在 `chinese_data`；实现上两条路径统一先拷贝到同一缓冲再处理（去重/触发匹配对象无歧义）。
- **去重**：播报前 `strcmp` 比较上次播报内容，相同且 D 秒内 → 跳过播报（LED 照常亮）。触发词卡**触发时的播报不受去重约束**（强制播报），播报后照常更新去重记录。
- **触发匹配**：遍历 `TRIGGER_RULES` 表子串搜索；每个规则配 `count[]`、`last_count_tick[]`、`triggered[]` 三个状态数组（上电清零）。
- **800ms 播报延时**：非阻塞——记录 `last_speak_tick`，主循环每圈检查是否已过 800ms，过了才继续读卡流程。

### 3.3 电机状态机（Motor_Process）

```
IDLE ──t≥A──▶ RAMPUP ──t≥A+B──▶ RUN
                                  │
                    ┌─────────────┴─────────────┐
                    │ E ≤ t < E+G（绝对秒）      │ 降速窗口（开机仅一次）
                    ▼                           │
                  SLOW(speed=target×F%)         │
                    └─────────────┬─────────────┘
                                  ▼
                            正常运行(speed=target)
                                  │
                    ┌─────────────┴─────────────┐
                    │ motor_trigger_flag 被置位  │
                    ▼                           │
              STOPPING（H=2s 线性减速至0）        │
                    ▼                           │
              WAIT（静止等待 I=10s）             │
                    ▼                           │
              RAMPUP（重新缓启动 B 秒）──────────┘
                    │
                    ▼
        （绝对时间 t≥stop_time 或 t≥1000s → STOP，保持0）
```

关键点：
- **绝对计时**：`t = HAL_GetTick() - start_tick`（start_tick 上电记录、永不清零），替代 RTOS 版的 `count_ms++`
- 停车序列阶段计时用 `state_tick`（进入当前状态时刻），每个阶段转移都刷新；STOPPING 减速 `speed = 触发时刻速度 × (1 - progress/H)`，progress 为进入该状态后的毫秒数
- 缓启动渐变：`speed = target × (t - A) / B`，每 `MOTOR_SLOW_RAMP_STEP_MS`(10ms) 更新一次 PWM；**重新缓启动不再经过晚启动 A**
- 触发停车时**计时不清零**；重启后 E 窗口已过不再降速；stop_time/1000s 上限继续按绝对时间判断
- 电位器停车时间在初始化时采样 20 次取平均后计算

### 3.4 裸机版时序权衡（重要）

| 场景 | 影响 | 对策 |
|---|---|---|
| TTS 发送阻塞（2~17ms/条，单块16字节） | 两状态机停顿 2~17ms | 缓启动 10ms 一档，最大"跳档"约 17ms，启动段有轻微顿挫但功能不受影响 |
| 800ms 播报延时 | 无（非阻塞） | — |
| 20ms 读卡超时 | 判定最多延后 ~17ms，不影响正确性（响应字节由接收中断无损捕获） | — |
| 输出串口发送（<3ms/条） | 几乎无影响 | — |

结论：功能完整，时序精度足够，比赛场景完全可用。

### 4.1 各文件来源与改动说明

| 文件 | 来源 | 改动 |
|---|---|---|
| `Card.c/h` | 案例**改造** | ① 回调 `temp_res==2`（读到卡号）时在 LEDLIGHT 态下**刷新全局"卡在场"时间戳**（供 LED 延迟熄灭判断）② 回调 `temp_res==3`（无卡）分支**不再递减 led_close_counts 主动熄灯**，熄灭改由状态机按 tick 判断 |

## 5. 数据输出串口协议（USART3，115200）

| 事件 | 输出格式 | 示例 | 开关 |
|---|---|---|---|
| 上电 | `[SYS] boot   LED=OFF MOTOR=STOP` | 初始化完成后输出一次 | `DBG_USART_ENABLE` |
| 读到卡（每条） | `[RFID] <长度>: <HEX字节(空格分隔)>` | `[RFID] 4: CC AB D1 F4` | `DBG_ECHO_RFID` |
| LED 变亮（边沿） | `[LED] ON` | LED_Sta(1) 时输出一次 | `DBG_ECHO_LED` |
| LED 熄灭（边沿） | `[LED] OFF` | LED_Sta(0) 时输出一次 | `DBG_ECHO_LED` |
| 电机状态变化 | `[MOTOR] <状态> speed=<当前速度>` | `[MOTOR] RAMPUP speed=345` | `DBG_ECHO_MOTOR` |

电机状态枚举：`IDLE`（未启动）、`RAMPUP`（缓启动中）、`RUN`（正常运行）、`SLOW`（降速窗口内）、`STOPPING`（减速停车中）、`WAIT`（静止等待）、`STOP`（已停止/到时停车）。

> 说明：LED 与电机输出均为**边沿触发**（状态变化才输出一次），缓启动每 10ms 的速度变化不逐条输出（避免刷屏）。读卡数据每条都输出。

### 上位机接线

```
MCU PB10(TX) ──── USB转TTL 的 RX
MCU PB11(RX) ──── USB转TTL 的 TX （可悬空，仅输出）
GND  ──────────── 共地（必须）
```

| 项 | 案例 | 本项目 |
|---|---|---|
| 芯片 | STM32F103C6T6（32KB/10KB） | STM32F103C8T6（64KB/20KB） |
| 操作系统 | FreeRTOS | **无（裸机主循环）** |
| 新增功能 | — | 去重播报、LED 卡脱离 C 秒熄灭、百分比降速窗口、多触发词停车重启、数据输出串口 |

| 延时机制 | vTaskDelay（可阻塞） | HAL_GetTick 时间差（非阻塞） |

## 8. 与 RTOS 版的代码对照（便于互转）

| 概念 | RTOS 版 | 裸机版 |
|---|---|---|
| 循环入口 | `RFID_Task` / `Motor_Control_Task`（任务函数） | `RFID_Process()` / `Motor_Process()`（主循环内调用） |
| 毫秒延时 | `vTaskDelay(ms)` | `WaitMs(&last_tick, ms)`（自封装 tick 差） |
| 1ms 计数 | `motor_control.count_ms++` | `t = HAL_GetTick() - motor_control.start_tick` |
| 长阻塞延时 | 直接 `vTaskDelay(800)` | 状态机内"记时刻→到点继续" |
| 开机一次性延时 | 任务开头 `vTaskDelay(2000)` | 初始化阶段直接阻塞 2s（无碍） |

> 两版共享：config.h（含触发词规则表）、hardware/ 全部驱动、读卡协议 Card.c（同样改造）、PWM/LED/ADC 控制逻辑。切换版本时只换 Task/ 层与 main.c 结构。
